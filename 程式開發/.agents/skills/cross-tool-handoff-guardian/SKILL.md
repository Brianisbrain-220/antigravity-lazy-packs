# 跨工具協作與交接防衛官 (cross-tool-handoff-guardian)

## 📌 核心目的
本 Skill 的核心任務是建立 **Antigravity ↔ Claude Code 雙工具無縫交接防線**。
兩個 AI 工具之間沒有直接通道，所有交換皆依賴使用者傳遞與 Obsidian Vault 同步。為防止資訊入口分歧、時間序日誌腐爛以及單方盲目覆蓋，**凡涉及交接、收工或換工具接手，必須嚴格執行本 SOP**。

---

## 🛡️ 六道防呆閘門 (The 6 Verification Gates)

當觸發「交接」或「收工」時，AI 必須依序通過以下 6 道檢核閘門，**不得跳過任何一關**：

### 🚪 Gate 1：禁止濫建交接檔與安全整併（最小共同祖先原則）
- **硬性禁令**：**嚴禁**在專案程式目錄建立任何 `README_HANDOVER.md`、`HANDOVER.md`、`TODO.md` 或獨立交接日誌。
- **安全防呆**：若發現專案目錄存在暫存交接檔，**先列出檔案內容摘要**，確認關鍵決策已合併至 Obsidian 駕駛艙後再予清理，避免誤刪手動筆記。
- **唯一事實來源 (SSOT)**：單一專案的進度與決議，**一律且僅能寫入 Obsidian 的 `Bound_Project_<專案名稱>.md`**。

### 🚪 Gate 2：雲端推播與部署提醒 (GAS / Cloud Sync)
- 若為 **Google Apps Script (GAS) 專案**：
  - 必須在該專案目錄執行 `clasp push`，確保雲端與本地程式碼 100% 同步。
  - 必須提醒使用者前往 Apps Script UI 執行 **「管理部署作業」➔「編輯」➔「建立新版本」➔「部署」**（避免 Webhook 仍跑舊版）。

### 🚪 Gate 2.5：領地狀態檢查（Protocol 規則 5）
- 若目標在 **Git 儲存庫** 中：
  - 動手前先執行 `git status` 檢查。
  - 若工作區乾淨 ➔ 允許執行交接收尾。
  - 若有**未提交的 WIP (對方進行到一半的工作)** ➔ 嚴禁覆蓋或提交，改為「產出架構規格交由對方執行」。

### 🚪 Gate 3：調閱並更新 Obsidian 專案駕駛艙（Protocol 規則 3 & 4）
1. **寫入前重讀**：透過各自工具支援的方式讀取 Vault 筆記（Antigravity 使用 Obsidian MCP；Claude Code 直接讀取本機 Vault 檔案系統），避免快取踩踏。
2. **更新開發紀錄**：在筆記末尾「開發紀錄表」追加最新日期、版本號、變更摘要與操作者。
3. **程式碼內部標記**：確認主程式（如 `Code.js` 或 `package.json`）頭部註解已同步更新版本號與 Change Log。

### 🚪 Gate 4：強制標準化「決議區塊 (Decision Blocks)」（Protocol 規則 2）
凡涉及架構轉向、模型更換、規則調整或重大技術取捨，**必須**在 Obsidian 筆記中產出標準決議格式（特別注意：對方立場必須如實反映，未經覆驗前狀態應為 `待對方確認`）：

```markdown
> **決議(YYYY-MM-DD)**: 一句話說明結論
> - **提出**: Claude / Antigravity / Brian
> - **理由**: 為什麼做此決定（最重要的核心脈絡）
> - **對方立場**: 已同意 / 待對方確認 / 有不同看法 (寫明具體內容)
> - **狀態**: `已共識` / `⚠️ 未達成共識` / `待對方確認`
> - 要推翻此決議前，請先閱讀以上理由。
```

### 🚪 Gate 5：產出對等交接指令 (Prompt for Next AI)
在對話最後，自動產出一組結構化的 Prompt，讓使用者能一鍵複製傳給 Claude / 下一個工具。

### 🚪 Gate 6：對等覆驗清單（Protocol 規則 6）
當一方回報「已完成」時，**另一方必須進行實質覆驗，而非盲目採信**。產出的交接指令必須明確包含「請覆驗以下 N 項」的 Checklist（包含功能驗證、權限規則或端點檢查）。

---

## 📋 跨工具交接範本 (Output Template)

當完成交接流程後，請依以下標準格式回報使用者：

```markdown
## 🤝 跨工具交接完成報告

- **專案名稱**：[專案名稱] (版本: [最新版本號])
- **Obsidian 駕駛艙**：`Bound_Project_[專案名稱].md` (已同步最新架構與決議)
- **程式碼同步**：已執行 `clasp push` / `git status` 乾淨
- **核心決議**：
  1. [決議一摘要] (`已共識` / `待對方確認`)

---

### 📋 請複製以下指令交接給 Claude / Antigravity：

「我目前正在開發 **[專案名稱]**，系統已推進至 **[最新版本號]**。
請你依照《ai-tool-handoff-protocol》，首先讀取 Obsidian 中的專案駕駛艙 **`Bound_Project_[專案名稱].md`** 了解最新架構演進與決議。

請協助執行以下【覆驗清單 (Verification Checklist)】：
1. [請覆驗項目 1：如 API 回應、功能邏輯]
2. [請覆驗項目 2：如決議區塊內容與狀態]
3. [接續開發任務 3]」
```
